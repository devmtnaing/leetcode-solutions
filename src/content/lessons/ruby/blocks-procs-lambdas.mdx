Ruby gives you three ways to pass a chunk of code around, and newcomers usually
learn them as a list of trivia. They're easier to hold onto as one idea with two
switches: **how it's passed** and **what `return` does inside it**.

## A block is not an object

A block is syntax, not a value. It rides along with a method call and nothing else:

```ruby
[1, 2, 3].each { |n| puts n }
```

You can't assign a block to a variable, because there's no object there to
assign. What a method *can* do is capture it:

```ruby
def twice(&blk)
  blk.call
  blk.call
end
```

That `&` is the conversion. On the way in it turns the block into a `Proc`; on
the way out — `some_method(&my_proc)` — it turns a `Proc` back into a block.
Same operator, both directions.

## Procs and lambdas are the same class

Here's the part that surprises people:

```ruby
p = proc { |x| x }
l = lambda { |x| x }
p.class  # => Proc
l.class  # => Proc
l.lambda? # => true
```

One class, one flag. The flag changes two behaviours.

**Argument checking.** A lambda is strict, a proc shrugs:

```ruby
lambda { |a, b| }.call(1)      # ArgumentError
proc   { |a, b| }.call(1)      # fine — b is nil
```

**What `return` means.** This is the one that bites in real code. Inside a
lambda, `return` returns from the lambda. Inside a proc, `return` returns from
the *enclosing method*:

```ruby
def with_lambda
  l = -> { return 10 }
  l.call
  20            # => 20
end

def with_proc
  p = proc { return 10 }
  p.call
  20            # never runs — the method already returned 10
end
```

## Which to reach for

Use a **block** when the code is only ever used at the call site — which is most
of the time, and why `each`, `map` and `tap` all take one.

Use a **lambda** when you're storing the behaviour: a validator, a callback, a
strategy in a hash. You want the strict arity and the local `return`, because
those are what make it behave like a function you can reason about in isolation.

Use a **proc** when you're deliberately exploiting the loose arity — which in
practice means when you're writing something that behaves like a block.
